# 逐光 / LightBearing · 产品需求 PRD

> Xuzuo Studio · API 26 only · v0.1 草案，等待用户审核；不代表编译验证。

**应用**：逐光 / LightBearing · **Bundle**：`com.hhyxx.LightBearing` · **代码仓库**：https://github.com/hhyxx1/LightBearing。

## 1. 产品定义

- 一句话价值：指定机位与目标太阳方位/高度后，获得可验证的候选时段并形成拍摄计划。
- 目标用户：风光、城市、建筑、旅拍摄影师；使用真实太阳方位判断拍摄时间，而不依赖盲目踩点。
- 用户价值判断：能否真实完成核心工作流，减少反复操作和不确定性；不要把炫酷视觉当成功能。
- 品牌标语：好光线，值得提前抵达。
- 商业假设：暂不写死收费价格；应先验证摄影师是否愿意为反向寻光、机位库与可靠时区付费。
- 不做的事：不提供无依据的云端天气或地形遮挡预测；离线本地计算是核心。

## 2. 产品交付边界

**这是已有工程的迭代 PRD，而非新项目初始化说明。** 首先检查 `hhyxx1/LightBearing` 的 `main` 和 `fix/core-quality-audit`，确认已实现、未落地的 R2 设计、现存签名与用户 RDB；保持已注册大写 Bundle Name `com.hhyxx.LightBearing`。以已有的 99 项宿主机测试/设备时区测试记录作为历史证据，但本次改版仍需重新测试，不得直接继承通过结论。

**完整功能范围**（以下每一条都必须实现或记录受 SDK/硬件限制的真实原因和可操作降级，禁止伪装已经完成）：

1. F01：太阳方位角/高度角的离线精确计算与基准测试
2. F02：日出日落、太阳正午、民用/航海/天文曙暮光及无升落状态
3. F03：可配置黄金/蓝调阈值；曲线与全天阶段色带同源
4. F04：24h 与非24h 本地日（23/23.5/24.5/25h）完整时间轴
5. F05：跨日期范围反向寻光：角度环形误差 + 高度容差 + 白昼过滤
6. F06：机位库与计划 CRUD、机位时区与 UTC 完整存储
7. F07：前台一次定位和手动坐标降级
8. F08：方位传感器能力探测、手动校正与误差提示
9. F09：离线方位图与可选地图集成
10. F10：计划卡 PNG / CSV 真实导出与外部校验
11. F11：本地历史、任务进度、长搜索取消与设置数据迁移
12. F12：手机紧凑布局、平板/大屏布局、暗色和浅色、无障碍
13. F13：跨日期线、极地、1969 负时间戳、DST 回拨/前跳异常处理
14. F14：未来可能的视线遮挡/天气扩展必须单独立项，默认不承诺

## 3. 关键用户工作流

1. 首次打开→跳过/完成引导→选择已有机位或通过表单新建机位→按机位时区显示当地今天。
2. 首页移动选中时刻→同一 selectedUtc 更新数值、曲线标记、UTC 偏移与光线阶段→点击“下一窗口”跳到窗口开始。
3. 反向寻找目标方向→输入角度/容差与日期范围→进度可取消→查看候选误差→加入拍摄计划。
4. 在回拨日选择两次相同本地时间→界面明确显示两种 UTC 偏移→用户手动选择→保存后原 UTC 不可漂移。
5. 选择导出→系统保存选择器→生成真实 PNG/CSV→返回 URI/错误/取消状态→外部打开验证。

## 4. 页面与导航信息架构

**12 个业务页面/独立路由**（系统 Picker、权限弹窗、确认框和操作系统分享面板不计入）。

| 路由 | 名称 | 用户任务 | 主操作 |
| --- | --- | --- | --- |
| `/home` | 今日光线 | 选定机位与当地日→当前太阳方位/高度、光线阶段、全天曲线、分段带、下一窗口 | 反向寻光 |
| `/sunpath` | 太阳轨迹 | 真实日期边界的曲线、日出日落/正午、时间选择、时区差异 | 保存当前时刻为计划 |
| `/reverse` | 反向寻光 | 目标方位与高度、容差、日期范围、白昼过滤、结果列表 | 搜索并加入计划 |
| `/locations` | 机位库 | 经纬度/时区/名称/备注、收藏搜索和编辑 | 添加机位 |
| `/compass` | 现场罗盘 | 传感器方位、太阳参考方向、磁偏角与校准提示 | 开始/暂停观测 |
| `/map` | 地图方位 | 可选地图、机位方向射线与离线极坐标方位图 | 设为当前机位 |
| `/planner` | 拍摄计划 | 选择机位、候选窗口、当地日期/时间、行前清单、备注与保存 | 保存计划 |
| `/calendar` | 光线日历 | 逐日光线窗口与计划、极地/跳日/无效状态 | 查看选中日期 |
| `/compare` | 时间比较 | 最多五日期的方位/高度与同日时段比较 | 新增比较日期 |
| `/settings` | 设置 | 主题、时区、角度单位、阈值、数据管理、隐私与诊断 | 保存设置 |
| `/placeDetail` | 机位详情 | 机位元数据、太阳位置复核、编辑与删除 | 编辑机位 |
| `/planDetail` | 计划详情 | 计划 UTC、当地时刻、复核结果、导出/删除 | 导出计划 |

手机一级入口优先保留 3–5 个，二级统一用 ArkUI `Navigation` 管理；平板布局根据内容宽度而非仅设备类型调整。专属工作台（相机、波形、太阳曲线、宏按钮、批量图片）允许沉浸式布局。

## 5. 数据与系统行为契约

- 用户新建、编辑、删除的结果必须从真实持久化读取，不使用演示数组替代。
- 所有导出与执行动作都应有实际可验证的文件或外设回执。
- 失败/取消不更改源数据；需要重试的任务保持可定位的错误状态。
- 项目数据和文件资产关联需要一致性校验、schema 迁移与删除清理。
- 任何已知设备限制要在发生场景显示，而不是藏在开发日志里。

## 6. 权限与风险边界

**权限预期（最终以 API26 SDK 审计为准）：**

- 前台定位：`APPROXIMATELY_LOCATION` / `LOCATION`，仅用户点击时申请
- 无后台定位；无相机和麦克风；完全离线主流程无需 INTERNET
- Map Kit 条件接入需真实服务资格，未配置时不强制索取

**关键不确定性：**

- 原型的曲线/色带按近似采样生成，生产不能把 5min fixture 当真值
- R2 纯 HTML 当前没有直接更新真实 HAP；必须逐项迁移
- 不改变 `com.hhyxx.LightBearing` 大小写、签名配置与老用户 RDB
- 极短目标时窗可能被粗采样跳过；搜索策略需完成短窗口/合并/分布回归
- 高纬极昼极夜及无本地日期时必须呈现明确状态

## 7. 非功能要求与质量属性

| 维度 | 必须达到的产品结果 |
| --- | --- |
| 稳定性 | 冷启动/前后台/系统中断后项目可恢复；无静默丢数据 |
| 性能 | 主要可见操作及时反馈，长任务带进度/取消；图片/视频避免一次性加载全部数据 |
| 可用性 | 导航一致，按钮均有真实行为；错误状态可操作；危险动作有确认或撤销 |
| 无障碍 | label、≥44vp 热区（目标 48vp）、高对比、减少动效 |
| 国际化 | 日期、单位与本地时区有一致解释；文本不直接嵌入插画 |
| 数据安全 | 无强制账号/上传，不对外泄露工作项目，导出明确告知用户 |
| 普通开发者兼容 | 不用受限 ACL、非公开系统 API 或未授权的第三方跨应用能力 |
