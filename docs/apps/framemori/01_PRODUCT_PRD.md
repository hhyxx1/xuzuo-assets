# 帧间 / FrameMori · 产品需求 PRD

> Xuzuo Studio · API 26 only · v0.3 草案，等待用户审核；不代表编译验证。

**应用**：帧间 / FrameMori · **Bundle**：`com.hhyxx.framemori` · **代码仓库**：（待创建独立仓库）。

## 1. 产品定义

- 一句话价值：将一次次稳定拍摄的照片变成节奏可调、可听可看的真实 MP4 动画。
- 目标用户：乐高、黏土、手工产品和模型动画创作者；需要可控拍摄和轻量专业逐帧剪辑。
- 用户价值判断：能否真实完成核心工作流，减少反复操作和不确定性；不要把炫酷视觉当成功能。
- 品牌标语：让每一帧，都有生命。
- 商业假设：假设轻买断或 Pro 解锁；首发前必须验证稳定相机与导出质量在目标用户中是否有价值。
- 不做的事：不承诺所有机型可锁 AE/AF/AWB；不提供虚假的可编码能力或后台长时拍摄。

## 2. 产品交付边界

**完整功能范围**（以下每一条都必须实现或记录受 SDK/硬件限制的真实原因和可操作降级，禁止伪装已经完成）：

1. F01：项目生命周期完整 CRUD；非破坏性原帧和编辑版本
2. F02：Camera Kit 检测相机、拍照与预览能力；手动模式可用性探测
3. F03：洋葱皮叠加前帧，透明度 0–100%，网格与安全边界辅助
4. F04：单帧拍摄、计时拍摄和可停止的间隔拍摄
5. F05：可用时锁定 AE/AF/AWB；不可用时提供清晰降级
6. F06：音量键/蓝牙快门只在真实允许的系统键/外设接口下启用
7. F07：逐帧排序、复制删除、帧时长、FPS 1–30 调整、撤销重做
8. F08：导入既有照片到帧序列；明确分辨率及 EXIF 方向处理
9. F09：帧亮度变化统计与阈值提示，不能保证绝对防闪烁
10. F10：导入/录音音轨，起始偏移与音量调整
11. F11：实时播放预览与实际成片时间长度一致
12. F12：逐帧编码生成真实 MP4，并在可用条件下封装音轨
13. F13：图片序列导出 ZIP，支持失败取消与恢复
14. F14：大型项目内存/缓存管理、编辑历史与错误恢复
15. F15：手机/平板界面适配并使用系列视觉规范

## 3. 关键用户工作流

1. 创建项目→选画幅/FPS→拍摄前权限说明→预览与能力探测→真实拍帧→缩略图入库→逐帧播放。
2. 启用洋葱皮→调整透明度→移动对象→按实际快门拍摄→选择上一帧叠加检查位置。
3. 时间轴长按选择帧→移动/复制/删除→撤销→调整局部时长→试听配音。
4. 导出界面选择尺寸/帧率→检查设备编码器→异步逐帧写入真实视频轨→音频可用时封装→外部播放器验证。

## 4. 页面与导航信息架构

**10 个业务页面/独立路由**（系统 Picker、权限弹窗、确认框和操作系统分享面板不计入）。

| 路由 | 名称 | 用户任务 | 主操作 |
| --- | --- | --- | --- |
| `/projects` | 项目首页 | 最近作品、排序、复制/重命名/删除、创建向导 | 新建项目 |
| `/capture` | 拍摄工作台 | 实时预览、拍摄键、洋葱皮、网格、定时/间隔、硬件状态 | 拍摄一帧 |
| `/timeline` | 逐帧时间轴 | 缩略帧、拖动排序、帧时长、剪切复制、批量选择 | 播放预览 |
| `/frame-editor` | 单帧编辑 | 无破坏性裁剪旋转与画布调整、撤销重做 | 应用变换 |
| `/audio` | 配音与音乐 | 导入/录制音频、调整起点/音量、试听 | 添加音轨 |
| `/stability` | 拍摄稳定性 | 曝光/对焦/白平衡锁定能力、帧亮度波动趋势 | 检查拍摄状态 |
| `/preview` | 成片预览 | 可选帧率、播放范围、循环/暂停和音频试听 | 生成导出 |
| `/export` | 动画导出 | MP4 编码设置、图片序列、音频、路径、进度 | 导出 MP4 |
| `/presets` | 拍摄预设 | 相机可用模式、洋葱皮透明度、构图网格、计时器 | 保存预设 |
| `/settings` | 设置与素材管理 | 主题、空间占用、缓存、原帧保留、隐私与诊断 | 清理缓存 |

手机一级入口优先保留 3–5 个，二级统一用 ArkUI `Navigation` 管理；平板布局根据内容宽度而非仅设备类型调整。专属工作台（相机、波形、太阳曲线、宏按钮、批量图片）允许沉浸式布局。

## 5. 数据与系统行为契约

- 用户新建、编辑、删除的结果必须从真实持久化读取，不使用演示数组替代。
- 所有导出与执行动作都应有实际可验证的文件或外设回执。
- 失败/取消不更改源数据；需要重试的任务保持可定位的错误状态。
- 项目数据和文件资产关联需要一致性校验、schema 迁移与删除清理。
- 任何已知设备限制要在发生场景显示，而不是藏在开发日志里。

## 6. 权限与风险边界

**权限预期（最终以 API26 SDK 审计为准）：**

- CAMERA：拍摄工作台首次使用时询问 user_grant
- MICROPHONE：仅“录制配音”时申请
- 照片/音乐：走用户系统 Picker，避免整个图库权限
- 导出目标：由用户选择系统保存路径

**关键不确定性：**

- Camera Kit 的手动对焦、白平衡、曝光固定由设备支持，不保证逐个都能锁定
- MP4 从照片序列编码不是 AVTranscoder 的简单转码，必须真实逐帧 VideoEncoder + Muxer
- HEVC/H.264、AAC 能力与分辨率/帧率受机型 codec 限制，需按能力矩阵选择
- 大帧数 PixelMap 的内存与释放必须监控；编码前不要一次性载入 500 帧
- 间隔拍摄只保证应用在前台且可控，不作后台定时/保活承诺

## 7. 非功能要求与质量属性

| 维度 | 必须达到的产品结果 |
| --- | --- |
| 稳定性 | 冷启动/前后台/系统中断后项目可恢复；无静默丢数据 |
| 性能 | 主要可见操作及时反馈，长任务带进度/取消；图片/视频避免一次性加载全部数据 |
| 可用性 | 导航一致，按钮均有真实行为；错误状态可操作；危险动作有确认或撤销 |
| 无障碍 | label、≥44vp 热区（目标 48vp）、高对比、减少动效 |
| 国际化 | 日期、单位与本地时区有一致解释；文本不直接嵌入插画 |
| 数据安全 | 无强制账号/上传，不对外泄露工作项目，导出明确告知用户 |
| 普通开发者兼容 | 不用受限 ACL、非公开系统 API 或未授权的第三方跨应用能力 |

## 8. 里程碑与真实交付要求

**以下是实现依赖，不是 P0/P1/P2 删减。**

1. Camera API26 与编解码可用性先做真机 probe，再确定可支持的质量挡位
2. 完成相机→持久化帧→时间轴→真实可播放无声 MP4 最小闭环
3. 补全部非破坏性编辑、音轨与图片序列导出
4. 加入拍摄稳定性面板、错误回退与大型工程性能
5. 素材获批后接入引导/图标，最后做长时真机稳定性

每完成一个依赖阶段都需要保留可运行工程、测试记录与真实设备限制说明。最后按 `04_ACCEPTANCE.md` 完整验收；未通过必须如实标注。

## 9. 审阅时重点确认

- 核心价值与目标用户是否准确。
- 是否接受所有目标功能的技术与验证成本，而不是假装“一次性全开发必然成功”。
- 页面数量/导航是否符合日常使用频率。
- 哪些能力必须离线、哪些可以条件使用网络或第三方 SDK。
- 下一阶段哪些素材值得制作，见 `05_ASSET_BRIEF.md`。
