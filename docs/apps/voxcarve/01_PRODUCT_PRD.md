# 声剪 / VoxCarve · 产品需求 PRD

> Xuzuo Studio · API 26 only · v0.3 草案，等待用户审核；不代表编译验证。

**应用**：声剪 / VoxCarve · **Bundle**：`com.hhyxx.voxcarve` · **代码仓库**：（待创建独立仓库）。

## 1. 产品定义

- 一句话价值：用可复核的文字区间与波形把口播“删错句、删长停顿、保留好段落”，导出真实剪辑结果。
- 目标用户：做短口播、访谈、课程和播客的创作者，愿意检查文字稿来提高剪辑效率。
- 用户价值判断：能否真实完成核心工作流，减少反复操作和不确定性；不要把炫酷视觉当成功能。
- 品牌标语：从文字，剪出好声音。
- 商业假设：语音剪辑已有成熟竞争者；不预设付费成立。只有大幅省时且可靠才考虑独立收费。
- 不做的事：不承诺无依据的词级时间戳、100% 自动无错剪辑或全格式 MP4 兼容。

## 2. 产品交付边界

**完整功能范围**（以下每一条都必须实现或记录受 SDK/硬件限制的真实原因和可操作降级，禁止伪装已经完成）：

1. F01：选择本地媒体、校验容器/编解码器/轨道、复制到沙箱
2. F02：媒体音轨真实解码为 PCM 分析数据，保留源文件不破坏
3. F03：调用真实可用的 Speech SDK 或明确拒绝并进入手动时间轴
4. F04：按 SDK 实际提供的时间粒度标注字幕和语句，允许手工校准
5. F05：分句选中→定位波形→试听→保留/删除可撤销区间
6. F06：波形缩放、区间吸附、时间微调、片段分割与合并
7. F07：静音候选基于真实音频 RMS 窗口计算，默认只提示
8. F08：字幕自动/手动生成、SRT 文件真正写出
9. F09：完整播放链：跳过删除区间，试听编辑结果不只是原文件
10. F10：WAV 导出必做：按剪辑图解码/拷贝保留采样实际生成
11. F11：支持的音频输出格式需编码器能力检查与可播放验收
12. F12：支持的视频格式需音视频重编码/封装与同步测试
13. F13：多项目版本、任务队列、失败恢复、超长文件内存控制
14. F14：录音仅用户手动开始并有明确暂停/停止
15. F15：系统权限/隐私/设备能力的解释与离线降级

## 3. 关键用户工作流

1. 用户选择一个 5 分钟口播视频→读取时长与轨道→生成波形→逐字稿转写或手动校准→预览。
2. 选中“嗯、呃”和重复句→播放对照→拖动边界对齐波形→确认删除→仅修改编辑图。
3. 点击停顿建议→逐个试听→确认/取消建议→撤销操作可恢复。
4. 导出 WAV/SRT→检查真实字节与音频长度；若 MP4 支持则重编码并验证音画同步。

## 4. 页面与导航信息架构

**10 个业务页面/独立路由**（系统 Picker、权限弹窗、确认框和操作系统分享面板不计入）。

| 路由 | 名称 | 用户任务 | 主操作 |
| --- | --- | --- | --- |
| `/projects` | 项目首页 | 本地项目、导入/录音、上次进度与素材状态 | 新建项目 |
| `/import` | 音视频导入 | 系统文件选择、格式/轨道分析、沙箱副本、空间预估 | 分析并导入 |
| `/transcript` | 文字稿 | 分句文本、置信/需复核状态、手工修改与时间绑定 | 核对时间区间 |
| `/timeline` | 音频剪辑台 | 波形、播放头、区间裁剪、吸附、撤销重做 | 删除/保留选段 |
| `/silence` | 停顿复核 | RMS 门限、区间建议、试听和手工确认 | 应用所选建议 |
| `/captions` | 字幕 | SRT 时间戳、段落字句、显示样式、导入导出 | 导出字幕 |
| `/preview` | 剪后试听试看 | 保留片段拼接试听、前后对比、跳转问题段 | 预览成品 |
| `/export` | 导出 | WAV、可用条件下 AAC/M4A、MP4、SRT、错误重试 | 实际生成文件 |
| `/history` | 历史与版本 | 可撤销操作、项目快照、源文件恢复 | 恢复版本 |
| `/settings` | 设置 | 识别语言、离线/在线说明、隐私、音频缓存、主题 | 保存设置 |

手机一级入口优先保留 3–5 个，二级统一用 ArkUI `Navigation` 管理；平板布局根据内容宽度而非仅设备类型调整。专属工作台（相机、波形、太阳曲线、宏按钮、批量图片）允许沉浸式布局。

## 5. 数据与系统行为契约

- 用户新建、编辑、删除的结果必须从真实持久化读取，不使用演示数组替代。
- 所有导出与执行动作都应有实际可验证的文件或外设回执。
- 失败/取消不更改源数据；需要重试的任务保持可定位的错误状态。
- 项目数据和文件资产关联需要一致性校验、schema 迁移与删除清理。
- 任何已知设备限制要在发生场景显示，而不是藏在开发日志里。

## 6. 权限与风险边界

**权限预期（最终以 API26 SDK 审计为准）：**

- MICROPHONE：仅点“开始录音”后申请
- 输入文件只使用用户文件/媒体选择器
- 默认不声明互联网权限；在线转写如果加入须单独审核
- 系统保存弹窗用于结果导出，不应要求广泛存储 ACL

**关键不确定性：**

- Core Speech 不一定提供稳定的词级时间戳；不能按文本字符比例伪造切点
- 音频变速、视频编辑需要重新计算音视频 PTS 和音量跨段平滑
- 断点和编解码格式错误可能产生静音、黑屏、音画不同步
- 错误剪辑会造成实际内容损失：默认可预览、可撤销、不覆盖源
- 长音频不得完全解码到内存；必须分块与磁盘缓存

## 7. 非功能要求与质量属性

| 维度 | 必须达到的产品结果 |
| --- | --- |
| 稳定性 | 冷启动/前后台/系统中断后项目可恢复；无静默丢数据 |
| 性能 | 主要可见操作及时反馈，长任务带进度/取消；图片/视频避免一次性加载全部数据 |
| 可用性 | 导航一致，按钮均有真实行为；错误状态可操作；危险动作有确认或撤销 |
| 无障碍 | label、≥44vp 热区（目标 48vp）、高对比、减少动效 |
| 国际化 | 日期、单位与本地时区有一致解释；文本不直接嵌入插画 |
| 数据安全 | 无强制账号/上传，不对外泄露工作项目，导出明确告知用户 |
| 普通开发者兼容 | 不用受限 ACL、非公开系统 API 或未授权的第三方跨应用能力 |

## 8. 里程碑与真实交付要求

**以下是实现依赖，不是 P0/P1/P2 删减。**

1. 优先验证 ASR 返回结构、音频 PCM 链和可用视频编解码格式
2. 先完成导入→手工时间轴→真实 WAV 导出的正确性闭环
3. 补可靠转写与校准 UI、停顿建议、字幕编辑与 SRT
4. 按能力矩阵实现音频格式与视频 MP4 导出，专门做 A/V sync
5. 完成长文件内存性能、安全与无障碍；素材审批后再接入插画

每完成一个依赖阶段都需要保留可运行工程、测试记录与真实设备限制说明。最后按 `04_ACCEPTANCE.md` 完整验收；未通过必须如实标注。

## 9. 审阅时重点确认

- 核心价值与目标用户是否准确。
- 是否接受所有目标功能的技术与验证成本，而不是假装“一次性全开发必然成功”。
- 页面数量/导航是否符合日常使用频率。
- 哪些能力必须离线、哪些可以条件使用网络或第三方 SDK。
- 下一阶段哪些素材值得制作，见 `05_ASSET_BRIEF.md`。
