# 店图匠 / StoroPix · 产品需求 PRD

> Xuzuo Studio · API 26 only · v0.1 草案，等待用户审核；不代表编译验证。

**应用**：店图匠 / StoroPix · **Bundle**：`com.hhyxx1.storopix` · **代码仓库**：（待创建独立仓库）。

## 1. 产品定义

- 一句话价值：批量导入→套用店铺统一风格→逐张复核→真实批量导出，减少重复修图。
- 目标用户：小型电商、手作、蜡烛/香皂/文具商家；需要手机上统一一批商品图片的风格。
- 用户价值判断：能否真实完成核心工作流，减少反复操作和不确定性；不要把炫酷视觉当成功能。
- 品牌标语：一批出好图，一店好风格。
- 商业假设：轻量免费试用 + 一次买断是待访谈假设，不能把预估售价写成真实市场事实。
- 不做的事：不承诺“一键 100% 完美抠图”或对任何材质的绝对颜色还原；不读取整个相册。

## 2. 产品交付边界

**完整功能范围**（以下每一条都必须实现或记录受 SDK/硬件限制的真实原因和可操作降级，禁止伪装已经完成）：

1. F01：多个店铺档案/项目/批次 CRUD 与本地持久化
2. F02：系统 PhotoPicker 多选、复制到沙箱并检查图片格式/尺寸/方向
3. F03：支持 JPEG/PNG 核心链、EXIF 旋转、横竖图安全裁剪与留白
4. F04：非破坏性图片处理参数：旋转/缩放/裁剪/色彩/对比度/锐度（可核实算法）
5. F05：店铺预设：画幅比例、背景色、边缘留白、输出尺寸与命名模板
6. F06：批量处理队列，支持取消、暂停/重试、进度与空间预估
7. F07：可选主体分割 Kit 能力探测，机型不支持时自动转手动模式
8. F08：纯色背景替换与边缘复核；对毛发/透明物体不保证无伪影
9. F09：水印文字/位置/透明度可调，避免侵权默认不添加平台 Logo
10. F10：批次“待处理/待复核/已导出/失败”状态清晰可追溯
11. F11：启发式质量检测：低分辨率、过曝、模糊、裁剪出界提醒
12. F12：原图/预览/最终效果对比与一键恢复原始参数
13. F13：JPEG/PNG 真实批量输出与命名冲突防护、系统保存
14. F14：选择性移除 GPS/EXIF 敏感元数据，默认提醒隐私
15. F15：手机/平板适配、空态、错误、低存储与极大图片性能保护

## 3. 关键用户工作流

1. 创建店铺档案→选店铺风格→选 1–20 张商品图→显示导入缩略图与检查结果。
2. 套用统一画幅/背景/留白→处理队列→逐张打开编辑器对比前后→标记质检。
3. 设备支持主体分割→显示可视化遮罩→用户放大边缘复核；设备不支持→正常裁剪/纯色板。
4. 批次导出→按命名模板生成文件→校验输出数量、尺寸与格式→外部文件管理器检查。

## 4. 页面与导航信息架构

**10 个业务页面/独立路由**（系统 Picker、权限弹窗、确认框和操作系统分享面板不计入）。

| 路由 | 名称 | 用户任务 | 主操作 |
| --- | --- | --- | --- |
| `/projects` | 店铺与项目 | 多店铺配置、最近批次、快捷创建与批次状态 | 新建批次 |
| `/import` | 批量导入 | 系统 PhotoPicker 多选、去重、尺寸/格式检查、排序 | 导入图片 |
| `/batch` | 批量工作台 | 左右缩略图列表、统一参数、批处理队列与统计 | 批量应用预设 |
| `/editor` | 单图编辑 | 原图/处理预览、裁剪旋转/缩放/色彩参数、撤销重做 | 保存非破坏性参数 |
| `/background` | 背景处理 | 纯色背景、构图留白、条件主体分割与手工调整 | 更新背景 |
| `/presets` | 店铺风格预设 | 画幅/背景色/边距/水印文案/输出尺寸 | 保存预设 |
| `/quality` | 质检清单 | 边缘粗糙/尺寸低/过曝/模糊启发式提示、人工确认 | 逐张复核 |
| `/compare` | 前后对比 | 批次原图/成品并排或滑动对比、参数回溯 | 确认出图 |
| `/export` | 批量导出 | 命名规则、JPEG/PNG、质量、尺寸、EXIF 清理、保存进度 | 生成成品 |
| `/settings` | 设置与空间 | 主题、默认尺寸、隐私、缓存/原图与历史清理 | 管理本地缓存 |

手机一级入口优先保留 3–5 个，二级统一用 ArkUI `Navigation` 管理；平板布局根据内容宽度而非仅设备类型调整。专属工作台（相机、波形、太阳曲线、宏按钮、批量图片）允许沉浸式布局。

## 5. 数据与系统行为契约

- 用户新建、编辑、删除的结果必须从真实持久化读取，不使用演示数组替代。
- 所有导出与执行动作都应有实际可验证的文件或外设回执。
- 失败/取消不更改源数据；需要重试的任务保持可定位的错误状态。
- 项目数据和文件资产关联需要一致性校验、schema 迁移与删除清理。
- 任何已知设备限制要在发生场景显示，而不是藏在开发日志里。

## 6. 权限与风险边界

**权限预期（最终以 API26 SDK 审计为准）：**

- 图片选择使用 PhotoPicker 用户选择授权；不申请整个相册权限
- 保存到系统文件选择器授权，不静默写入任意用户目录
- 不需要 CAMERA 和 MICROPHONE；若未来拍商品照应另行定义权限
- 不使用受限 ACL；离线主流程不声明 INTERNET

**关键不确定性：**

- 透明玻璃、毛发、复杂背景的分割误差明显；文案只承诺“辅助抠图”
- Color profile、JPEG 色域、元数据和色温会影响实拍颜色一致性
- 巨型照片批次可能导致 OOM；必须分批/分辨率分级处理
- 商家的风格差异较大，预设应可复用但不硬锁唯一风格
- 输入图库 URI 可能过期，必须在有效期内保存沙箱副本

## 7. 非功能要求与质量属性

| 维度 | 必须达到的产品结果 |
| --- | --- |
| 稳定性 | 冷启动/前后台/系统中断后项目可恢复；无静默丢数据 |
| 性能 | 主要可见操作及时反馈，长任务带进度/取消；图片/视频避免一次性加载全部数据 |
| 可用性 | 导航一致，按钮均有真实行为；错误状态可操作；危险动作有确认或撤销 |
| 无障碍 | label、≥44vp 热区（目标 48vp）、高对比、减少动效 |
| 国际化 | 日期、单位与本地时区有一致解释；文本不直接嵌入插画 |
| 数据安全 | 无强制账号/上传，不对外泄露工作项目，导出明确告知用户 |
| 普通开发者兼容 | 不用受限 ACL、非公开系统 API 或未授权的第三方跨应用能力 |

## 8. 里程碑与真实交付要求

**以下是实现依赖，不是 P0/P1/P2 删减。**

1. 完整本地非 AI 图像导入/处理/导出链先打通
2. 建立店铺预设/批次队列/非破坏性编辑和质检系统
3. Core Vision 主体分割做 SDK26 与真机能力探测，只有能用才接入
4. 大图性能、多批次与真实外部文件验收
5. 素材获批后补图标/入门示例/空态与商店图

每完成一个依赖阶段都需要保留可运行工程、测试记录与真实设备限制说明。最后按 `04_ACCEPTANCE.md` 完整验收；未通过必须如实标注。

## 9. 审阅时重点确认

- 核心价值与目标用户是否准确。
- 是否接受所有目标功能的技术与验证成本，而不是假装“一次性全开发必然成功”。
- 页面数量/导航是否符合日常使用频率。
- 哪些能力必须离线、哪些可以条件使用网络或第三方 SDK。
- 下一阶段哪些素材值得制作，见 `05_ASSET_BRIEF.md`。
