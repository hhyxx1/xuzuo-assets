## 0. 已有项目的测试溯源与本轮验收边界

StoroPix 不是空工程。已有 [源码](https://github.com/hhyxx1/storopix) 的 `documents/DEVICE_VALIDATION.md`、`documents/FOREGROUND_DEVICE_ACCEPTANCE_20261106.md`、`documents/PRD_CLOSURE.md` 记录了历史编译与部分设备验收。下表 `NOT_RUN` **仅表示本轮系列设计改造尚未重新执行对应测试**，不能据此断言原版功能未实现或未测试。新的 `PASS` 必须附本轮代码 SHA、设备与证据；此前历史结果可追溯但不自动计入新设计验收。

## 0. 签收原则

- 任何 `PASS` 必须附设备型号/OS API、测试时间、操作步骤与可复核证据。
- UI 原型截图不是 HAP 证明；SDK probe 不代表完整业务。
- GitHub main 上的历史测试不自动算到新分支。

## 4. 横向兼容与韧性

| 场景 | 验收要求 |
| --- | --- |
| 屏幕 | 360/390/430vp、宽屏 ≥600vp、横竖屏；无内容/按钮裁切 |
| 主题 | 深/浅/跟随系统保持数值与业务状态不变 |
| 字体 | 至少 1.3× 字号与屏幕阅读器导航可用 |
| 权限 | 初次拒绝、系统撤销、设置重开、设备能力缺失均有有效路径 |
| 存储 | 空间不足/系统保存面板取消/导入文件丢失/缓存清理安全 |
| 长任务 | 取消、错误重试、重启恢复、重复快速点击不会重复写入 |
| 设备 | 模拟器与真机分别记录；不能拿模拟器相机或网络当全部实测 |
| 资源 | 无未授权字体/图片/签名秘密、无超大未优化插画 |
