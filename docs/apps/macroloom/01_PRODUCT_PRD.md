# 键阵 / MacroLoom · 产品需求 PRD

> Xuzuo Studio · API 26 only · v0.3 草案，等待用户审核；不代表编译验证。

**应用**：键阵 / MacroLoom · **Bundle**：`com.hhyxx.macroloom` · **代码仓库**：（待创建独立仓库，必须包含 Windows Agent）。

## 1. 产品定义

- 一句话价值：通过安全局域网配对，让一个面板按钮触发已授权 Windows 动作，并拿到真实执行回执。
- 目标用户：Windows 办公、演讲、直播和视频剪辑用户；希望用鸿蒙手机作可靠的自定义快捷键控制台。
- 用户价值判断：能否真实完成核心工作流，减少反复操作和不确定性；不要把炫酷视觉当成功能。
- 品牌标语：一个按钮，串起工作流。
- 商业假设：存在 Macro Deck、Touch Portal 等低成本/免费替代；强调低延迟与可靠性后再验证买断意愿。
- 不做的事：不在鸿蒙端模拟其他应用输入；不提供未授权的任意远程 shell/PowerShell，也不承诺跨公网。

## 2. 产品交付边界

**交付范围包括两个软件**：HarmonyOS HAP + Windows Agent。只有手机端代码或只有 UI 原型均不构成产品完成。手机不直接调用 Windows SendInput；全部动作从 Windows 本地受信 Agent 执行。

**完整功能范围**（以下每一条都必须实现或记录受 SDK/硬件限制的真实原因和可操作降级，禁止伪装已经完成）：

1. F01：手机端 Deck 多页网格 CRUD、布局模板与真实按压反馈
2. F02：Windows 10/11 必交付 .NET 8 Agent，安装/卸载/托盘与安全状态
3. F03：局域网发现或手动添加 IP，严禁自动开放公网端口
4. F04：电脑生成稳定身份与一次性配对挑战，手机确认指纹，电脑二次确认
5. F05：WSS 连接与凭据安全存储、重连心跳和服务能力协商
6. F06：明确版本的 JSON 协议与消息 ID、ACK、去重、期限控制
7. F07：安全动作白名单：媒体键、PPT 操作、允许的热键、用户批准的应用
8. F08：宏编排：有序步骤、等待、终止条件、执行超时、人工确认
9. F09：OBS WebSocket 5.x 可选集成，需要独立用户配置与授权
10. F10：Windows 本地紧急停止、远控暂停、解绑设备、查看审计记录
11. F11：软件更新时协议版本协商，不兼容给可解释提示
12. F12：Deck 与宏 JSON 导入导出（不导出 Token/密钥）
13. F13：弱网与 Wi-Fi 切换重连，避免重复发送不可逆指令
14. F14：手机和平板适配、动效、可访问性与触觉反馈
15. F15：严格限制 Windows 锁屏、UAC、管理员会话和安全桌面访问

## 3. 关键用户工作流

1. Windows Agent 启动→显示一次性二维码→手机扫描→核对设备指纹→电脑端点击“允许”→持久信任并建立 WSS。
2. 用户编辑按钮→选“PPT 下一页”→保存→点击→手机发送 command ID→Agent 校验→执行→返回 ACK 及耗时。
3. 掉线→按钮变灰/排队策略明确→重连后仅安全地重发可幂等消息→消息 ID 去重。
4. 用户创建多步宏→审阅动作链→试运行/干运行→确认正式运行→执行结果与错误码可回看。

## 4. 页面与导航信息架构

**10 个业务页面/独立路由**（系统 Picker、权限弹窗、确认框和操作系统分享面板不计入）。

| 路由 | 名称 | 用户任务 | 主操作 |
| --- | --- | --- | --- |
| `/home` | 控制台首页 | 已信任电脑、连接状态、常用面板和最近指令 | 打开面板 |
| `/pair` | 首次配对 | 电脑二维码/短码、指纹确认与限时授权 | 发起配对 |
| `/deck` | 控制面板 | 可自定义多页按钮网格、长按编辑、动作反馈 | 执行动作 |
| `/designer` | 面板布局 | 按钮尺寸/排序/颜色/图标/热区、复制与删除 | 保存布局 |
| `/macros` | 宏编辑器 | 步骤顺序、等待、条件检查、超时、取消与确认 | 运行测试 |
| `/actions` | 安全动作库 | PPT/媒体快捷键、受信程序启动、OBS 特殊操作 | 新增安全动作 |
| `/devices` | 电脑设备 | 电脑身份、公钥指纹、权限级别、解绑与暂停 | 管理信任设备 |
| `/activity` | 执行记录 | 每条动作 ID、开始/结束/失败码与耗时 | 查看失败原因 |
| `/diagnostics` | 连接诊断 | 局域网连通、端口、证书、心跳与延迟 | 重试连接 |
| `/settings` | 设置与备份 | 主题、触觉、布局导出/导入、安全选项与隐私 | 导出配置 |

手机一级入口优先保留 3–5 个，二级统一用 ArkUI `Navigation` 管理；平板布局根据内容宽度而非仅设备类型调整。专属工作台（相机、波形、太阳曲线、宏按钮、批量图片）允许沉浸式布局。

## 5. 数据与系统行为契约

- 用户新建、编辑、删除的结果必须从真实持久化读取，不使用演示数组替代。
- 所有导出与执行动作都应有实际可验证的文件或外设回执。
- 失败/取消不更改源数据；需要重试的任务保持可定位的错误状态。
- 项目数据和文件资产关联需要一致性校验、schema 迁移与删除清理。
- 任何已知设备限制要在发生场景显示，而不是藏在开发日志里。

## 6. 权限与风险边界

**权限预期（最终以 API26 SDK 审计为准）：**

- HarmonyOS `INTERNET` 普通权限（局域网通信）
- 二维码扫描依 Scan Kit 的 SDK26 可用性检查授权
- 不使用受限 ACL、不获取鸿蒙跨应用自动化权限
- Windows 侧安装时说明本机端口、防火墙、常驻托盘与可信设备配置

**关键不确定性：**

- 没有 Windows Agent 的 HarmonyOS 应用无法独立控制电脑
- 网络控制存在命令重放、凭据窃取、未授权执行风险；默认拒绝未知设备
- 某些系统窗口/UAC/锁屏属于安全边界，不能绕过
- 自动重连若重发多次可能多次点击，必须 ID 去重和过期验证
- 允许自定义任意脚本会扩大攻击面；当前不允许远端任意脚本执行

## 7. 非功能要求与质量属性

| 维度 | 必须达到的产品结果 |
| --- | --- |
| 稳定性 | 冷启动/前后台/系统中断后项目可恢复；无静默丢数据 |
| 性能 | 主要可见操作及时反馈，长任务带进度/取消；图片/视频避免一次性加载全部数据 |
| 可用性 | 导航一致，按钮均有真实行为；错误状态可操作；危险动作有确认或撤销 |
| 无障碍 | label、≥44vp 热区（目标 48vp）、高对比、减少动效 |
| 国际化 | 日期、单位与本地时区有一致解释；文本不直接嵌入插画 |
| 数据安全 | 无强制账号/上传，不对外泄露工作项目，导出明确告知用户 |
| 普通开发者兼容 | 不用受限 ACL、非公开系统 API 或未授权的第三方跨应用能力 |

## 8. 里程碑与真实交付要求

**以下是实现依赖，不是 P0/P1/P2 删减。**

1. 先完成 Agent 安全协议、WSS 配对和一键回执的威胁建模
2. 电脑 Agent + 鸿蒙 app 能在局域网真实配对并执行一个允许动作
3. 完整 Deck 设计器、宏编排、动作库与日志/诊断
4. 弱网、重连、证书变更、解绑、安全桌面与 OBS 集成
5. 素材审批后补启动图标/引导并做可用性和上架准备

每完成一个依赖阶段都需要保留可运行工程、测试记录与真实设备限制说明。最后按 `04_ACCEPTANCE.md` 完整验收；未通过必须如实标注。

## 9. 审阅时重点确认

- 核心价值与目标用户是否准确。
- 是否接受所有目标功能的技术与验证成本，而不是假装“一次性全开发必然成功”。
- 页面数量/导航是否符合日常使用频率。
- 哪些能力必须离线、哪些可以条件使用网络或第三方 SDK。
- 下一阶段哪些素材值得制作，见 `05_ASSET_BRIEF.md`。
