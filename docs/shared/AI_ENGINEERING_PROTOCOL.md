# 编程 AI 统一执行约束（给 Codex / Claude Code / DevEco Code）

## 读取顺序

1. 读 `README.md`、`docs/00_START_HERE.md`、`docs/shared/*`。
2. 读当前 App 的六份核心文档。
3. 如果 App 仓库已存在，先分析真实代码、提交差异、签名信息与当前测试；不允许盲目重新初始化。
4. 先输出工具链可用性与风险登记，再开始实现。

## 工作规则

- 功能按依赖逐项落地，但不能以“第一版 MVP”作为理由私自永久删掉 PRD 功能。
- 每实现一个里程碑至少编译并跑针对性测试；最终验收严格按 `04_ACCEPTANCE.md`。
- 源数据保留；文件转码与资源导出必须真实完成；任何模拟数据都只能在明确的测试 fixture 中出现。
- 用户可见文案不能声称“离线识别/全机型 4K/AI 抠图/准确方位”而没有设备证据。
- 复杂系统 Kit 必须查 SDK26 `.d.ts` 与官方 API Reference；错误码必须捕获并向用户解释。
- 不自行更改 LightBearing AGC 大小写包名、签名/profile、现有核心算法与用户存储 schema。
- 使用独立分支，写清每次修改范围，提供 PR 与测试记录；没有明确授权不推 main。
- 修改用户设备上的数据或新增测试机位需明确限定测试对象，不删除用户真实资料。

## 每轮完成后固定回报

```text
变更分支/提交 SHA：
受影响文件：
功能完成清单及真实证明：
未完成/设备条件项：
编译与测试命令、结果（NOT_RUN 必须写明）：
实际截图或视频（只有实测才给）：
下一项依赖工作：
```

## 材料边界

- 设计 HTML 只作为交互和视觉参考；生产必须以 ArkUI 原生实现。
- 用户尚未审阅素材需求时，不得自动生成图像或写入 `assets/`。
- 任何正式图标/素材必须在素材审核后才集成，防止反复返工。
