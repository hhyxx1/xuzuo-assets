# 统一 QA 与发布规范

## 全项目必做检查

- 正确性：核心算法真实数据单测，输入异常、边界、国际化、负时间与换日（若适用）。
- 功能性：每页按钮点击真实生效；前后台恢复；新建/编辑/删除/撤销；异常任务重试。
- 视觉：360/390/430vp + 至少一个 600+vp；Dark/Light；放大字体；长文本/不同语言。
- 性能：滚动和拖动不卡顿；进度显示；长任务可取消；内存增长/泄漏检查。
- 权限：未授权、拒绝、撤销、服务关闭、设备硬件不可用；不应无限权限循环。
- 导出：外部软件独立打开真实文件；保存取消不留“成功”通知。
- 安全：恶意文件、异常超长文本、媒体容器破损、网络未授权请求和边界格式。
- 可访问性：屏幕阅读器可读控制、触控热区、色彩对比、减少动效、键盘返回。

## 状态标注规范

| 状态 | 意义 | 证据标准 |
| --- | --- | --- |
| `PASS_DEVICE` | 真实目标机型通过 | 设备型号/系统版本、操作步骤、日志与结果 |
| `PASS_EMULATOR` | 仅模拟器通过 | 模拟器配置、实际测试记录 |
| `PASS_HOST` | 宿主机纯函数/协议测试通过 | 测试命令与汇总 |
| `DESIGN_PREVIEW` | 仅 HTML/截图视觉设计 | 原型、尺寸、静态/交互范围 |
| `BLOCKED` | 权限/SDK/环境阻碍 | 明确失败码与降级路线 |
| `NOT_RUN` | 没有执行 | 不填假数据 |
| `FAIL` | 失败 | 最小复现、根因、修复状态 |

## 自动化质量闸门

1. 静态检查/格式/ArkTS 编译无错误。
2. 核心业务单测及边界测试全部通过。
3. 模拟器 UI 主要链路及回归通过。
4. 真机目标功能单独验证，未运行项目保留 `NOT_RUN`。
5. 出具截图比对与实际文件/外设执行验证。
6. 版本号、包名、权限声明、签名与资源许可核对。

## 禁止的验收行为

- 将“编译成功”写成“真机功能完整验证”；将“显示有时间码”当成“音频准确剪切”；将“显示连接成功”当成“Windows 实际执行”。
- 在发布日志里埋掉受限 API 或已知严重缺陷。
- 自动化测试直接改真实用户私有数据；测试必须使用专门测试对象、可清理并获允许。
