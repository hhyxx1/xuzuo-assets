# 阶段 07 · 代码审查、跨轮续跑、PR 和交接提示词

这个阶段可在任一阶段出现阻塞/上下文较长时使用，也用于最后发布前回归。

## 发给 AI

请继续当前 App 的真实开发，不要忘记或重复做已经完成的工作。**先重新读取当前本地磁盘和 Git 状态**，而不是只依赖上次聊天摘要。检查 xuzuo-assets/main 的现行 docs/development 与本 App PRD，以及本 App 的 docs/dev/IMPLEMENTATION_MATRIX.md、WORK_LOG.md、API_AUDIT.md、TEST_REPORT.md、RISKS.md 和当前 feature 分支。

1. 给出“实际代码已存在/编译已验证/设备已验证/设计已覆盖/尚未实现”五栏证据矩阵。历史报告只作参考，当前 SHA 的测试需独立确认；不要说已跑其实没跑。
2. 审查所有 diff：是否删除 PRD 功能、有没有伪造业务数据、硬编码图形/时间码、是否引入被禁止的渐变/大海报、是否把独立文件/DB 签名覆盖、是否泄露密钥；比对 ArkTS 静态限制、本机 SDK 和官方 API Reference。必要时反向搜索 Kit 真正可用条件，修正错误代码。
3. 选择剩余最重要、能够实际完成的任务，**直接继续编码、编译、测试、修复**。目标是在当前阶段完成验收，不要只给泛泛规划。遇到单项设备阻塞，继续做可验证的独立模块/测试和真实降级，不要宣布全部完成。
4. 一旦完成一个真实阶段，在 feature branch 提交有意义的 commit，并为用户准备可审阅 PR（如果拥有授权写权限）；不得擅自向生产 main 强推、删分支、创建公开仓库或发布 HAP。代码审查必须包含安全/版权/数据迁移与用户操作回归。
5. 不要把编程 AI 自己写的模拟测试全部说成“真机已通过”。基于日志记录 PASS_DEVICE、PASS_EMULATOR、PASS_HOST、FAIL、BLOCKED 或 NOT_RUN，证据不足的状态只能是 NOT_RUN。
6. 维护跨轮 CONTINUE.md，用具体的上下文交接：目标 App、仓库路径、当前分支/SHA、SDK与机型、真正使用过的 Skills、已验证 API、文件路径、命令/错误码、功能完成矩阵、遗留问题、下一步三项动作。不要保存用户私钥/token/敏感信息。
7. 对任何本轮涉及的官方 API，提供明确实际访问的开发者官方文档 URL、检查本机 .d.ts 声明的方法和日期。文档访问不了说访问不了。
8. 最后自查：是否真的在开发 App 而非只新增 docs？若只写了文档而无可运行生产改动，明确告知“尚未实现”，继续实现当前最短闭环。

请现在对工作区进行自检并执行剩余工作，直到本阶段完成或遇到必须由我授权/实体设备才能解决的阻碍，再按统一阶段格式汇报。
