# 阶段 06 · 全面测试、可靠性、安全和发布就绪审查

## 发给 AI

现在按本 App 04_ACCEPTANCE.md、docs/shared/QA_RELEASE.md、PRIVACY_SECURITY.md 完成阶段 06。不是只给测试计划，**实际在当前授权的环境运行所有可执行测试**，修复回归与高风险错误，无法运行的项目严格记为 NOT_RUN。

【功能与质量矩阵】
1. 逐 PRD 功能 ID 对照实际源码和可复验路径，覆盖 UI 行为、真正的数据状态、持久化、退出重启、取消、重复点击、恢复、权限拒绝/撤销、服务中断/设备不支持、异常输入和安全控制。所有页面至少正常、空、加载、错误、权限/设备条件（适用时）。
2. 真实编译：目标 SDK26 原生 HAP 的 Debug 构建、Release 构建（签名安全前提下）、ArkTS 静态检查、单元测试、编码器/协议/数学算法测试；日志需含命令、版本、SHA、退出码、失败栈、修复提交。
3. UI：360/390/430vp 手机、至少一个 ≥600vp 布局；深/浅主题、长文本/字体放大、横屏、返回栈、手势/键盘输入、屏幕阅读器、动画减弱、对比度与点击热区。需展示真实 DevEco Preview、模拟器或真机证据；**HTML 演示截图永远不算 ArkUI 真机通过**。
4. 性能：首次加载、长列表滚动、图形刷新、媒体批量/长媒体、导出时间、内存/文件句柄、后台恢复、低内存、离线与重试，采集可量化日志。
5. 全面边界：LightBearing 的 DST/极昼/历史时间与角度环绕；FrameMori 的崩溃中断、200+帧/音频同步与真实 MP4；VoxCarve 的多时长/破损媒体/时间码对齐与实际外部播放；MacroLoom 的断网/伪造命令/重放/证书过期/授权撤销/多步动作部分失败。
6. 安全：最小权限、访问记录保护、导入文件路径遍历/格式伪装、无敏感日志、网络证书、没有未授权自启动/录音、没有 root/隐藏 API；检查所有正式素材许可证。
7. 发布前身份审计：bundleName 与 AGC 完全一致、versionCode/Name 策略、权限声明、SDK/设备能力、签名配置**只核对不泄露或擅自修改**。若需证书密钥、账号登录、AGC 管理、上架操作或公开仓库，必须请求用户明确批准；不要把它们当作默认可自动执行任务。
8. 导出独立验证：光线计划 PNG/CSV 真数据、动画 MP4/帧序列外部播放器检查、声音 WAV/SRT 等外部读取、Windows Agent 实际机器状态和收据。由不同读取路径或工具检验结果，不仅验自己写的 UI。
9. 在 docs/dev/TEST_REPORT.md、ACCEPTANCE_REPORT.md、PERFORMANCE.md、SECURITY_REVIEW.md、RELEASE_READINESS.md 写明每个案例 PASS_DEVICE / PASS_EMULATOR / PASS_HOST / FAIL / BLOCKED / NOT_RUN 和证据链接/日志。
10. 修复优先级：会丢数据、越权、安全、错误导出与核心计算严重偏差是发布阻塞。功能完成率、遗留问题和能力条件不能隐瞒。

- 代码分支和 SHA、完整 diff/变更范围，构建产物的真实存在路径（仅有文件才能声称），人工复验步骤。
