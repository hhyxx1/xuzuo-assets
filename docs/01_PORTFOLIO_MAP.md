# 序作 Studio · 五款作品定位与依赖地图

**事实基线（2026-11-12 核查）**：LightBearing 和 StoroPix 已有独立源码仓库；StoroPix 开发者确认已上架 0.2.0，但公开主分支仍保留版本 0.1.0 的应用配置。它不是从零开发计划。详见 [包名与发布版本事实登记](03_PACKAGE_AND_RELEASE_REGISTRY.md)。

## 共同产品原则

- 独立工具，单项任务高效完成；一个 App 不强行装下五种不相关功能。
- Local-first：无账号也能体验核心链路；网络/AI/云服务只是用户同意后的增强。
- 功能的真实性优先于宣传：算法计算、导出结果、设备执行必须在外部可验证。
- 同源的视觉质量：约束品牌、交互与基础组件，但专业编辑台/地图/相机/宏面板各自独立设计。
- 个人开发者可维护：先设计精密的边界与测试，再实现大功能，不依赖受限 ACL 或系统签名。

## 仓库分工

- `xuzuo-assets`：品牌规范、PRD、页面设计、资源生成记录、视觉稿与验收文档。不作为生产 App 的源码根目录。
- `LightBearing`：逐光唯一真实的 ArkTS 工程仓库，保留现有历史与分支。
- 其他四款：另开独立仓库；键阵需要 Windows Agent 子工程或单独仓库。
- 各 App 引用本库中的明确版本号/资源 SHA，而非动态读取 main 路径作为运行时依赖。

## 推荐开发与验收顺序

1. 逐光：保留已测数学内核，把成熟的 R2 视觉方案落地成 ArkUI；验证正确性和布局。
2. 帧间：聚焦拍摄、帧编辑与真实 MP4 输出，验证相机能力与稳定性。
3. 键阵：先做 Windows Agent + 授权协议 + 小面板，完成闭环后扩动作库。
4. 店图匠：先完成不依赖 AI 的批处理核心，再确认主体分割的机型支持。
5. 声剪：在词/句时间戳与音视频编码方案验证后进入大规模实现；否则极易做成假编辑器。

这个顺序是**开发依赖和风险顺序**，不是删掉后续功能。每个 PRD 均写明完整目标与真实验收条件。当前顺序可在用户审阅后改变。

## 统一发布门槛

- 真实 API 26 构建通过；签名/包名正确；默认数据私有且功能离线可解释。
- 所有可见按钮有可观察真实效果；外部播放器/系统操作能验证导出与指令。
- 真机 UI 走查、无障碍、大小屏与长时稳定性至少达到各 App 验收单。
- 对未实现/依赖设备能力的功能明确标为未支持，不能以设计图掩盖。
