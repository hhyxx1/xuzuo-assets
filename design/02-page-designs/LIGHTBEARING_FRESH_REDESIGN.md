# LightBearing · 全新 UI 设计的权威边界

> **用户明确要求 2026-11-12**：LightBearing 现有 UI 很不满意，视觉 **整体从零设计**，**不要参考旧 UI / UI-1B-R2**。

## 这个约束具体意味着什么

- **不会**复用已有 HomePage、ObservationPanel、Charts 的视觉布局、旧设计稿 CSS、字号比例、卡片层级、图标结构或导航信息密度作为新方案的视觉来源。
- **允许保留并使用**原项目可靠的太阳位置/日界/DST/反向寻光算法、数据模型与测试覆盖。算法不是 UI 风格；重做 UI 不等于重写业务计算。
- 四款的色彩、字体、按钮、导航、状态等统一由 XzUIKit token 定义；LightBearing 专业画布（太阳轨迹/现场罗盘/光线日历）由新组件设计且数据与领域层绑定。
- 示例 SVG 只展示目标视觉布局，不声明旧工程已有实现。本层与旧界面之间不存在“参考旧版视觉但局部替换”的兼容条款。
- 当 PDF/PRD 旧文档中的视觉描述与这套新的独立屏幕设计冲突，**以本套新视觉交付为优先**；功能定义与时区/算法精度以实际业务约束为优先。

## 首页新路线
1. 主视觉：编辑式“光线观察工作台”，深蓝底 + 琥珀/青色双指标；大范围柔和日光主题，但不以装饰图冒充实际角度。
2. 信息层级：先给下一拍摄窗口和选中机位的关键状态，再给清晰的数值、简洁操作与导航。
3. 用户可选择机位/时间/目标并进入独立详情；避免旧版控件照搬。
4. 辅助页面 S02–S12 的业务路由按已审核 PRD 覆盖，所有状态与异常有页面单独规格。
5. 最终 ArkUI 的外观与新设计一致，功能逻辑与原项目可靠代码一致；两条标准分别测试。

## 需要后续实际验证
新设计并未执行 ArkUI 编译、HAP 适配、真机视觉回归。待用户审图后，在 LightBearing 独立源码仓库新分支实施，并对旧数据迁移和算法回归逐项签收。
